# 0014. Прототип толпы на встроенной графике

Отчёт от 23 ноября 2026 года по замерам на настольном ПК. Статус выбора движка для целевого ноутбука остаётся открытым.

## Вывод для проекта

Базовый город Three.js выдержал цель в каждом из трёх прогонов в обычном окне. При 300 анимированных жителях и 50 движущихся машинах на встроенной Radeon настольного Ryzen 5 7600X получено от 143,70 до 143,85 кадра/с. Эту конфигурацию можно использовать как исходный вариант для проверки на ноутбуке. Доступен только этот ПК, поэтому результат для ноутбука пока неизвестен. По плану следующий шаг при провале базового профиля на целевой машине — повторить ту же нагрузку на Babylon.js. [Критерий прототипа](../architecture.md#риски-и-прототипы) · [Порядок разработки](0007-crowd-prototype-before-scene.md).

**Среднее скрывает остановки.** Второй оконный прогон `high` дал 1,00 кадра/с, второй прогон `atlas` — 59,44. В обоих есть интервалы длительностью около секунды. Они учтены в таблице. В контрольной серии для тех же профилей интервалы уложились в 33,34 мс. Эти замеры не позволяют установить причину пауз или приписать их стоимости второй текстуры. Ещё одна попытка `atlas` была прервана при скрытии вкладки и повторена. [Распределение длительности кадров](evidence/0014-crowd-frame-times.csv).

## Нагрузка и воспроизводимость

- Тестовые жители идут по тротуарам шести кварталов. Движение рук и ног рассчитывает вершинный шейдер. Упрощённый житель содержит 498 треугольников, детализированный — 4 196, машина — 452. На окружение приходится 3 828 треугольников. Например, в базовом кадре 300 × 498 + 50 × 452 + 3 828 = 175 828. В начале и в конце каждого учтённого замера центры всех 350 моделей находились в границах камеры.
- Вариант `atlas` добавляет к палитре текстуру рисунков на 24 фасадных панелях. Вариант `glass` выделяет стёкла машин в отдельный непрозрачный материал. Результаты относятся к этим моделям. Скелетная анимация импортированных GLB, прозрачное стекло, частицы и тени требуют отдельных замеров. Бюджет полигонов для всех игровых ассетов по этому испытанию не утверждаем. [Вопросы к прототипу от художников](../art-direction.md#после-прототипа-толпы) · [Решение о текстурах](0009-before-stage-1-assets.md).
- Windows 11 Pro, сборка 26300, драйвер AMD 32.0.13066.12, Three.js 0.186.1, Chrome 157.0.8103.79, WebGL2, буфер 1600 × 900, масштаб рендера 1. Во всех учтённых прогонах контекст WebGL сообщил `AMD Radeon(TM) Graphics (0x0000164E) Direct3D11`. На этом ПК по умолчанию браузер выбирал RTX 3060 Ti, для замера встроенный адаптер указан при запуске процесса.
- Четыре профиля × три повтора × два режима = 24 учтённых замера. Каждый начинался с 5 секунд прогрева, затем записывались интервалы как минимум за 20 секунд. Порядок профилей менялся между повторами. При фиксированных seed 42 и времени 3 с повторный снимок совпал побайтно, при 4 с изображение изменилось.
- Исходное измерение — время между двумя вызовами `requestAnimationFrame`, за которое счётчик нарисованных кадров сцены увеличился на один. В CSV указаны режим, профиль, номер повтора, длительность интервала в мс и число таких кадров. FPS = 1000 × сумма `frames` / сумма произведений `interval_ms × frames`. Для `low` в окне это 8 631 кадр / 60,0205 с = 143,80 кадра/с. [Данные для пересчёта](evidence/0014-crowd-frame-times.csv) · [События кадров браузера](https://developer.mozilla.org/en-US/docs/Web/API/Window/requestAnimationFrame).

## Как повторить на ноутбуке

1. Открыть переносимый файл `Pupulta-crowd.html` в Chrome или Edge. Файл работает без сервера, сети и установки зависимостей. SHA-256 измеренной версии — `a96e6fd7e6702fce96d113590ed9ca61267c03c997769a9ac8407aaf371650c8`.
2. Выбрать низкую детализацию, одну текстуру и один материал. Нажать «Начать замер» и оставить окно открытым до конца трёх повторов.
3. Нажать «Скачать JSON». Сохранить модель ноутбука и режим питания вместе с отчётом. В JSON проверить фактический адаптер, ширину и высоту кадра. Для прямого сравнения использовать буфер 1600 × 900. Затем повторить остальные профили из таблицы.
