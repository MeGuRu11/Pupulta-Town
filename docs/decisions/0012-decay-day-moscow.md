# 0012. День порчи сменяется в полночь по Москве

Дата: 2026-10-29. Решил владелец проекта в треде PR 2 первого среза: из двух вариантов (полночь UTC, то есть 03:00 по Москве, и полночь по Москве) выбрал полночь по Москве. Уточняет [0008](0008-grid-sizes-decay.md): там сказано, что порча считается по календарным дням, но не сказано, по какому времени.

## Решение

- Календарный день просрочки сменяется в 00:00 по московскому времени (UTC+3).
- Срок задачи — дата без времени. Задача просрочена с 00:00 по Москве следующего дня.
- Время одно для всего проекта, а не для каждого города или игрока: ступень порчи у всех одинаковая.

## Почему

- Владелец работает по московскому времени. При полуночи UTC здание пачкалось бы в 03:00 по Москве, и в 00:30 задача со вчерашним сроком ещё выглядела бы чистой.
- Часовой пояс у города в модели данных не задан. Поле добавить можно, но в срезе нет второго часового пояса, на котором его проверить.

## Что из этого следует

- В коде это фиксированное смещение +180 минут, константа `DECAY_DAY_UTC_OFFSET_MINUTES` в `packages/shared`. Базу часовых поясов подключать не нужно.
- \[Certain\] В базе часовых поясов ICU у `Europe/Moscow` смещение +03:00 и зимой, и летом с 2015 по 2026 год (проверено в Node 2026-10-29). \[Likely\] Летнее время в России отменено с 26 октября 2014 года федеральным законом № 248-ФЗ от 21.07.2014; текст закона я не открывал.
- Если Россия снова введёт сезонный перевод часов, константу придётся заменить расчётом по `Europe/Moscow`.
- База в PR 3 считает день так же: дата текущего момента по UTC+3.
- Если в проекте появятся игроки из других часовых поясов, порча для них всё равно будет сменяться в полночь по Москве, пока у города не появится свой часовой пояс.
