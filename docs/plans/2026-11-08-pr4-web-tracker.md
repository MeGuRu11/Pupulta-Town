# PR4: интерфейс городов и командных задач

## Цель и границы

Реализовать PR4 из утверждённого первого среза: регистрация и вход по почте, восстановление сессии, города и приглашения, панель задач S/M с назначениями и сменой статуса, Realtime. Место для будущего города остаётся частью интерфейса; 3D относится к PR5. Гостевые приглашения, задачи L, экономика и личная комната остаются за границами среза.

Ветка `feat/web-tracker` основана на `feat/db-cities-tasks`: PR3 ещё не слит в main. Изменения настройки Docker сохранены отдельным коммитом базы ветки. PR4 оформляется отдельным зависимым pull request без слияния существующих draft PR.

## Изменения

- `apps/web`: официальный Supabase JS SDK, типы текущей схемы, публичная Vite-конфигурация без привилегированных ключей, слой запросов и RPC.
- Отдельная чистая логика формы, ролей, фильтрации задач и часов. Права по-прежнему проверяет база; клиент показывает доступные действия.
- React: Auth, список и создание городов, приглашение/присоединение, участники и панель задач. Состояния загрузки, пустых списков, ошибок и отправки. Интерфейс на русском с адаптацией к узкому экрану.
- Realtime подписан на выбранный город; смена города/выход очищают подписку и данные. Повторное подключение обновляет снимок. Запоздавший ответ старого города или сессии не заменяет текущий экран.
- Один источник времени для интерфейса и будущей сцены; фиксированные время и seed допускаются только при явно включённом тестовом режиме. Порча рассчитывается общей функцией, не хранится в клиенте или БД.
- Пример публичных переменных, инструкция запуска и CI/e2e-конфигурация для локального Supabase. Тесты не подключаются к hosted-базе и не используют service role.

Состояние задач сохраняется после перезагрузки. Проверить отсутствие действий создания у исполнителя; полномочия RPC дополнительно покрыты pgTAP PR3.

## Источники

Context7 не смог получить документацию (`fetch failed`). Проверка API выполняется по первичным источникам:

- [Supabase Auth signUp](https://supabase.com/docs/reference/javascript/auth-signup).
- [Auth events](https://supabase.com/docs/reference/javascript/auth-onauthstatechange): callback не должен ожидать другие вызовы SDK.
- [Postgres Changes](https://supabase.com/docs/guides/realtime/postgres-changes): события таблиц с RLS доступны только пользователям, которым разрешено чтение; клиентская фильтрация не заменяет RLS. Удаление и повторное подключение требуют корректного обновления снимка.
- Локальный контракт: `docs/plans/2026-11-06-pr3-db-cities-tasks.md`.
