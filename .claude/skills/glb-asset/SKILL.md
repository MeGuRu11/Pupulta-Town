# Модель из Blender в проект

## Требования к файлу

- Формат glTF 2.0, один файл `.glb`.
- Единицы — метры, ось Y вверх.
- Точка опоры в центре основания модели.
- Габариты кратны клетке сетки города (размер клетки — в `docs/concept.md`).
- Здания собираются из модулей: этапы стройки и ступени порчи — отдельные узлы, а не отдельные файлы.
- Люди: одно общее тело и скелет на всех, одежда — сменные части.

## Экспорт из Blender

Версия Blender у команды — 5.2.3 LTS. Модели рисуют люди; ИИ проверяет сцену и экспортирует, но не моделирует сам без просьбы.

Перед экспортом:

- Единицы сцены — метрические, Unit Scale 1.0.
- Масштаб и поворот объектов применены (Ctrl+A → All Transforms).
- Имена узлов зданий — `stage_*`, `decay_*`, `tint_*` из `docs/art-direction.md`, раздел 4.
- Лицевая сторона смотрит в −Y Blender: после экспорта это +Z glTF.

Экспорт без окна, скриптом из папки этого скилла (`.agents/skills/glb-asset/export_glb.py`):

```bash
blender -b model.blend --factory-startup --python-exit-code 1 --python .agents/skills/glb-asset/export_glb.py -- assets/<name>.glb
```

Blender из Steam не лежит в `PATH`. На Windows он обычно в `C:\Program Files (x86)\Steam\steamapps\common\Blender\blender.exe`; если нет, путь видно в Steam: Свойства → Установленные файлы → Обзор.

Скрипт падает, если единицы не метры или масштаб не применён, и печатает габарит в осях glTF и имена узлов верхнего уровня. Габарит сверь с клеткой 2 м, низ по Y должен быть 0, центр по X и Z — 0.

Настройки экспортёра в скрипте: GLB, +Y вверх, модификаторы применяются, не больше 4 костей на вершину, без Draco, камер и света. Сжатие делаем потом `gltf-transform`, не экспортёром.

Если подключён MCP-сервер Blender (установка в `docs/ai-environment.md`), те же проверки можно делать в открытой сцене до экспорта. Код через MCP выполняется без защиты: не открывай чужие `.blend` и не удаляй данные без просьбы человека.

Код для Blender 5.x: API заметно изменился с 4.x. Не опирайся на память — ищи в документации Python API (через MCP-инструмент поиска или docs.blender.org/api/5.2). Предпочитай `bpy.data` и `bmesh` операторам `bpy.ops`, которые зависят от контекста и без окна часто падают.

## Проверка

1. `pnpm check:assets` — проверка проекта: габариты, точка опоры, имена узлов, бюджет полигонов.
2. `gltf-transform validate <file>.glb` — соответствие спецификации glTF.
3. `gltf-transform inspect <file>.glb` — что внутри: сетки, материалы, текстуры, анимации.

## Сжатие

`gltf-transform optimize <in>.glb <out>.glb --texture-compress webp`

После сжатия снова запусти `pnpm check:assets` и открой модель в сцене: `optimize` может менять иерархию узлов, а модули зданий ищутся по именам узлов.
