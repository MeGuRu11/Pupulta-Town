# Пупульта Town: правила для ИИ-агентов

Этот файл читают все агенты проекта: Claude Code (через `CLAUDE.md`), ChatGPT и Codex.
Держи его коротким: Codex по умолчанию читает не больше 32 КиБ инструкций.

## Проект

Геймифицированный трекер задач в виде живого 3D-городка в браузере.

- Город = проект команды, в городе до 20 участников. Роли: руководитель, исполнитель, гость.
- Задача становится объектом по размеру: S — мелкий объект (ларёк, фонарь, клумба), M — дом, L — большое здание, которое достраивается по подзадачам.
- Два трекера. Командный: задачи создаёт и раздаёт руководитель. Личный: «личная комната», человек пишет задачи себе сам, их никто не видит, просрочек нет.
- Просроченная командная задача портит здание (грязь, граффити, дефект, ремонт, пожар по мере просрочки). Закрытие задачи чинит здание, прогресс не теряется.
- Рейтинг за неделю, месяц и год. Постоянного рейтинга нет.

Подробности: `docs/concept.md`, `docs/architecture.md`, принятые решения в `docs/decisions/`.
Не пересматривай решения из `docs/decisions/` без прямой просьбы человека.

## Стек

- TypeScript везде, монорепозиторий на pnpm.
- `apps/web` — React + Vite, 3D через React Three Fiber (Three.js).
- `packages/sim` — симуляция жизни города: чистый TypeScript без three, React и DOM.
- `packages/shared` — общие типы и константы.
- `supabase/` — миграции Postgres и тесты прав доступа на pgTAP.
- Позже: `apps/walk-server` — Colyseus для прогулок аватаров.

## Команды

Все команды запускаются из корня репозитория. `pnpm test:db` появится вместе с `supabase/` (PR 3 первого среза).

- `pnpm install`
- `pnpm dev` — клиент локально
- `pnpm typecheck`, `pnpm lint`
- `pnpm test` — модульные тесты (Vitest)
- `pnpm test:db` — тесты базы (нужен Docker: `supabase start`, затем `supabase test db`)
- `pnpm test:e2e` — браузерные тесты (Playwright)
- `pnpm check:assets` — проверка `.glb`
- `pnpm verify` — typecheck, lint, test и check:assets разом. Запускай перед каждым коммитом.

## Цикл работы

1. **Пойми задачу.** Прочитай нужные части `docs/`. Если задача неоднозначна или спорит с `docs/decisions/`, спроси человека до кода.
2. **План.** Для задачи больше одного файла запиши план в `docs/plans/ГГГГ-ММ-ДД-тема.md`: что меняем, какие файлы, какие тесты докажут результат.
3. **Сначала тест.** Напиши тест, который падает без твоего изменения.
4. **Код.** Минимальное изменение, после которого тест проходит.
5. **Проверка.** `pnpm verify`. Красное — чини и запускай снова. Не заканчивай работу на красном.
6. **Ревью.** Пройди по diff с чек-листом «Code Review Rules» ниже.
7. **Pull request.** Маленький, одна тема. В описании: что сделано, как проверено, чего не сделано.

## Инварианты

Нарушение инварианта — ошибка, даже если тесты зелёные.

- `packages/sim` не импортирует three, react, `@react-three/*`, DOM API и сеть.
- В симуляции нет `Math.random()` и `Date.now()`. Только генератор случайных чисел от seed города и время, переданное параметром. Один seed и одно время дают одну и ту же картину.
- Права доступа живут в базе (RLS), не в клиенте. Командные задачи создаёт и назначает только руководитель. Личные задачи видит только автор. Монеты, очки и этапы зданий пишет только база.
- Ступень порчи здания не хранится. Она вычисляется из срока задачи и текущей даты.
- Фоновая жизнь города (жители, машины) считается на клиенте и не идёт по сети.
- В городе не больше 20 участников.
- Ассеты: `.glb` (glTF 2.0), метры, ось Y вверх, точка опоры в центре основания, размеры кратны клетке сетки.

## Тесты

- Логика и симуляция: Vitest, файлы `*.test.ts` рядом с кодом.
- Каждое правило доступа в базе: тест pgTAP в `supabase/tests/` на разрешённый и на запрещённый случай.
- 3D-сцена: скриншот Playwright с фиксированным seed и временем.
- Никогда не удаляй, не пропускай (`skip`, `only`) и не ослабляй тест, чтобы стало зелёным. Если тест неверен, скажи об этом человеку.

## База данных

- Схема меняется только новой миграцией в `supabase/migrations/`. Миграции, которые уже есть в `main`, не редактируй.
- Через MCP Supabase подключайся только к dev-проекту и только на чтение. Production не трогай.

## Git

- Одна ветка на задачу: `feat/…`, `fix/…`, `chore/…`, `docs/…`.
- Не пушь в `main` напрямую и не переписывай чужую историю.
- Не коммить секреты: ключи, токены, `.env`. Пример переменных лежит в `.env.example`.

## Язык

- Код, имена, сообщения коммитов: английский.
- Документация, планы, описания pull request и общение с людьми: русский.

## Code Review Rules

Отмечай в ревью:

- нарушение любого инварианта выше;
- изменение схемы без миграции или правило доступа без теста pgTAP;
- новую зависимость без объяснения в описании PR;
- отключённый, удалённый или ослабленный тест;
- логику в компоненте React, которую можно вынести в `packages/sim` или `packages/shared`;
- секреты или персональные данные в коде, логах и тестах.
