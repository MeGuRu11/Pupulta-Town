# Изменение базы

Права доступа в этом проекте живут в базе, поэтому любое изменение схемы идёт тремя частями: миграция, политика RLS, тест pgTAP.

## Шаги

1. Создай миграцию: `supabase migration new <short_name>`. Файл появится в `supabase/migrations/`.
2. Напиши SQL. Для каждой новой таблицы: `alter table <t> enable row level security;` и политики. В политиках используй `(select auth.uid())`.
3. Создай тест: `supabase test new <short_name>`. Файл появится в `supabase/tests/`.
4. В тесте проверь разрешённый и запрещённый случай. Пользователя подставляй так:
   ```sql
   set local role authenticated;
   set local request.jwt.claim.sub = '<uuid пользователя>';
   ```
   Тест оборачивай в `begin; … rollback;`, начинай с `select plan(N);`, заканчивай `select * from finish();`.
5. Подними базу локально (`supabase start`, нужен Docker) и прогони `supabase test db`.

## Правила проекта

- Миграции, которые уже есть в `main`, не редактируй. Нужна правка — новая миграция.
- Командные задачи создаёт и назначает только руководитель города: тест на исполнителя, который пытается создать задачу, обязателен.
- Личные задачи видит только автор: тест на чужого пользователя обязателен.
- Монеты, очки и этапы зданий клиент не пишет напрямую, только функции базы.
- `supabase db push` и любые команды против удалённого проекта запускает человек, не агент.
